## Part D — Compare the Two Approaches

### 6. Did both approaches return the same records in all five tests? If not, identify the difference and investigate its cause.

Yes. In all five tests both columns showed the same books, in the same order, with the same record count:

1. All books: 20 records in both columns, ordered by price from lowest to highest.
2. Search `autem`: 9 records in both columns.
3. Low stock (below 10): 1 record in both columns, the book with stock 3.
4. Combined (`alias` + below 10): 1 record in both columns.
5. Reset: the filters cleared and both columns returned to the default 20 records.

This is expected. Both query chains use the same `where` conditions, the same `orderBy('amount')` and the same `limit(20)`, so they produce the same SQL. If the results ever differed, the first thing to check is whether one chain has a condition, sort or limit that the other does not.

### 7. Which parts of the code are similar, and which parts differ?

Similar (identical in both chains):

- `->when($search, ...)` with `where('title', 'like', '%' . $search . '%')`
- `->when($lowStock, ...)` with `where('stock', '<', 10)`
- `->orderBy('amount')`
- `->limit(20)`
- `->get()`

Different:

- The starting point. Query Builder starts with `DB::table('books')`. Eloquent starts with `Book::query()`.
- What each row becomes. Query Builder returns plain `stdClass` objects. Eloquent returns `Book` model objects.
- Extra features. Only Eloquent rows can use model features such as relationships, casts, accessors, `$book->update()` and `$book->delete()`.

### 8. Why does the Query Builder example not require a Book model, while the Eloquent example does?

Query Builder works directly with a table name. `DB::table('books')` tells it which table to query, and it builds the SQL from that. It does not need to know what the table represents in the application.

Eloquent is an ORM (object-relational mapper). Each model class is linked to one table, and each row becomes an object of that class. `Book::query()` needs the `Book` model so Eloquent knows which table to use (`books`, taken from the class name) and which class to turn each row into.

### 9. Does `Book::all()` automatically make a query faster than `DB::table('books')->get()`? Explain.

No. Both send the same SQL to the database: `select * from books`. The database does the same work either way, so the query itself is not faster.

Eloquent is usually a little slower in PHP, because it builds a `Book` model object for every row, while Query Builder returns plain objects. With 100 books the difference cannot be noticed. With very large results, Query Builder can use less memory and time. Speed depends on the SQL, the indexes and the number of rows returned, not on which tool wrote the query.

### 10. Give one situation where you would prefer Eloquent and one situation where Query Builder may be suitable.

Prefer Eloquent for normal application work on whole records: creating, editing and deleting a book, or using relationships (for example, a book that belongs to a country). The model keeps the code short and readable.

Query Builder may be suitable for reports and bulk work that do not map neatly to one model, such as totals with joins and `GROUP BY` (for example, total stock per country), bulk updates, or reading many rows where building a model object for each row would be wasteful.

### Answers for the worksheet

SQL template:

```
select * from `books` where `title` like ? and `stock` < ? order by `amount` asc limit 20
```

What the bindings represent:

Each `?` in the SQL template is a placeholder. The bindings are the real values that fill those placeholders, in order: `%alias%` fills the first `?` (the title search, with `%` wildcards for "contains"), and `10` fills the second `?` (the stock threshold). Laravel sends the template and the values to MySQL separately, using prepared statements. Because user input is never pasted into the SQL text, a search like `' OR 1=1 --` is treated only as text to search for, which protects the page from SQL injection.

## Part F — Final Challenge: Custom Stock Threshold (how to do it)

Start after Part E, with the original Eloquent query restored.

### Step 1 (worksheet 12). Read and validate `stock_limit` in the controller

In `BookQueryController.php`, replace these two lines:

```php
        $search = $request->input('search', '');
        $lowStock = $request->boolean('low_stock');
```

with:

```php
        $validated = $request->validate([
            'stock_limit' => 'nullable|integer|between:0,1000',
        ]);

        $search = $request->input('search', '');
        $lowStock = $request->boolean('low_stock');
        $stockLimit = (int) ($validated['stock_limit'] ?? 10);
```

- `nullable` allows the box to be empty, which uses the default 10.
- `integer` rejects text such as `abc`.
- `between:0,1000` rejects values outside the range.

### Step 2 (worksheet 13). Use the threshold in both queries

The low-stock part appears twice, once in the Query Builder chain and once in the Eloquent chain. Change both from:

```php
            ->when($lowStock, function ($query) {
                $query->where('stock', '<', 10);
            })
```

to:

```php
            ->when($lowStock, function ($query) use ($stockLimit) {
                $query->where('stock', '<', $stockLimit);
            })
```

`use ($stockLimit)` passes the variable into the function. The value goes through `where()`, so it becomes a binding (`?`), not text added to the SQL. This follows the worksheet rule: "Do not concatenate user input into raw SQL."

### Step 3. Send the threshold to the view

Change the `return` at the end of `index()` to:

```php
        return view('pages.book-query-comparison', compact(
            'search', 'lowStock', 'stockLimit',
            'queryBuilderBooks', 'eloquentBooks'
        ));
```

### Step 4 (worksheet 11). Add the `stock_limit` input to the form

In `resources/views/pages/book-query-comparison.blade.php`, the search box is in `<div class="col-md-6">`. Change `col-md-6` to `col-md-4` so the row still fits, then add this block right after the search box's closing `</div>`:

```blade
        <div class="col-md-2">
            <input type="number" name="stock_limit" class="form-control"
                   min="0" max="1000" placeholder="Stock threshold"
                   value="{{ $stockLimit }}">
            @error('stock_limit')
                <small class="text-danger">{{ $message }}</small>
            @enderror
        </div>
```

Change the checkbox label from:

```blade
                <span class="form-check-label">Stock below 10</span>
```

to:

```blade
                <span class="form-check-label">Stock below {{ $stockLimit }}</span>
```

If validation fails, Laravel goes back to the page and `@error('stock_limit')` shows the message under the box.

### Step 5 (worksheet 14). Display the selected threshold

Add this line right after `</form>`:

```blade
    <p>Selected stock threshold: <strong>{{ $stockLimit }}</strong></p>
```
